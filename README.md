# Sales Prediction API

[![Python CI](https://github.com/thentsation/sales-prediction-project/actions/workflows/pipeline_python.yaml/badge.svg)](https://github.com/thentsation/sales-prediction-project/actions/workflows/pipeline_python.yaml)
[![Docker CI/CD](https://github.com/thentsation/sales-prediction-project/actions/workflows/pipeline_docker.yaml/badge.svg)](https://github.com/thentsation/sales-prediction-project/actions/workflows/pipeline_docker.yaml)

> Leia em [português](README.pt-br.md).

Predicts the sale amount for a coffee-shop transaction from a `RandomForestRegressor`, trained on a real point-of-sale dataset (2176 transactions), tracked with MLflow and served with FastAPI.

An in-depth write-up of the productization of this project — including a scaler that was silently never applied at inference — is available in [ARTIGO.md](ARTIGO.md) (pt-br) / [ARTIGO.en-us.md](ARTIGO.en-us.md) (en-us).

## Project structure

```text
src/
├── models/
│   ├── base_model.py     # ModelInterface
│   └── sales_model.py     # SalesPredictor: RandomForestRegressor + StandardScaler
├── utils/data_loader.py    # CSV -> encoded train/test split
├── api/main.py              # FastAPI: POST /predict, GET /health
└── main.py                   # load -> train -> log (MLflow) -> save
```

## Getting started

```bash
make install    # creates .venv and installs deps
make train      # trains the model, logs to MLflow, saves models/sales_predictor.pkl
make serve      # uvicorn --reload
```

- Swagger UI: http://127.0.0.1:8000/docs
- MLflow UI: `.venv/bin/mlflow ui` (reads `./mlruns`, gitignored, generated by `make train`)

### Making a prediction

```bash
curl -X POST http://127.0.0.1:8000/predict \
  -H 'Content-Type: application/json' \
  -d '{"features": [1705833000, 0, 12, 4]}'
```

`features` is `[datetime_epoch_seconds, cash_type_encoded, card_encoded, coffee_name_encoded]` — the same four columns and encoding `src/utils/data_loader.py` produces at training time. This API doesn't (yet) accept raw categorical strings; see the article for why.

Run with Docker instead:

```bash
make docker-build
make docker-run
```

## Telvax version

`telvax/` has this project written in [Telvax](https://github.com/telvax/telvax):
* training: the same features, label encoders and split;
* the model: standard scaling and a random forest of 100 trees, from the [`learn`](https://github.com/telvax/learn) package;
* MLflow logging, from the [`mlflow`](https://github.com/telvax/mlflow) package;
* the service, with the same `/health` and `/predict`.

The predictor is one value (`SalesPredictor`: the fitted scalers, the forest and the label encoders) saved with
`std.model`. Loading it gives the scaling with the model, so the API cannot predict without it, and a file of another type
is refused. Nothing is unpickled.

```sh
cd telvax
tvpm run main                                             # train, save models/sales_predictor.tvxmodel
MLFLOW_TRACKING_URI=http://localhost:5000 tvpm run main   # also log mae and mse to MLflow
telvax serve src/service.tvx --port 8000                  # GET /health, POST /predict
telvax build --serve src/service.tvx -o sales-api         # one binary; docker/telvax.Dockerfile builds the image
```

The same request to both services gives the same prediction: `{"features": [1711000000.0, 0, 100, 3]}` gives 38.70 from
both, the Python one given its datetime as described below. On the same 418 test rows:

| | MAE | RMSE | R² |
|---|---|---|---|
| Python (scikit-learn) | 0.0122 | 0.0969 | 0.9996 |
| Telvax | 0.0152 | 0.1248 | 0.9994 |

The forests differ because the bootstrap draws come from another generator. Each version's own split also differs:
Python's gives MAE 0.0268 and Telvax's MAE 0.0152. Training takes 56 s in Telvax (the trees are grown in the
interpreter) against about 3 s.

Found while porting: `datetime` is documented as epoch seconds, but with pandas 3 `pd.to_datetime(...)` is in
milliseconds, so `.astype("int64") / 10**9` gives thousandths of a second. A request with real epoch seconds is then far
outside what the Python model was trained on. The Telvax version uses real seconds, as the API description says.

## Development

```bash
make test        # pytest
make coverage     # pytest with coverage report
make lint         # ruff check
make format       # ruff format
make typecheck    # mypy
```

CI runs ruff, pytest (coverage gate), mypy and pip-audit on every push/PR, plus a scheduled daily run. Docker images are built, scanned with Trivy, and published to GHCR on `main`. Dependabot keeps pip, the Docker base image, and GitHub Actions up to date, with patch/minor bumps auto-merged. Releases are tagged automatically with [python-semantic-release](https://python-semantic-release.readthedocs.io/).
